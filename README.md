# Pig Legends — ARNO of the Dimwood

A dark-fantasy action prototype: you are **ARNO**, the last knight of the
Sowenmarch, a pig in plate armour, riding into a wood that eats sound. Sword,
dodge and bring down the wolves before the dark takes you.

**Live page:** <https://dmppmd132-glitch.github.io/Pig-Legends/>

Everything in the build is generated by code — terrain, forest, characters,
animations, textures, sound. There are no binary asset downloads, which is why
the whole game ships as one repository and installs as a PWA that keeps working
offline.

## Play

| Action  | Keyboard           | Touch                        |
| ------- | ------------------ | ---------------------------- |
| Move    | `W A S D`          | left virtual stick           |
| Sprint  | `Shift`            | `RUN` toggle                 |
| Slash   | `J` / `Z` / click  | `ATTACK` (three-hit chain)   |
| Roll    | `Space` / `K` / right-click | `ROLL`              |
| Lock on | `Q` / `Tab`        | `LOCK`                       |
| Pause   | `Esc` / `P`        | `‖`                          |
| Restart | `R`                | button on the death screen   |

Camera: drag with a finger or the mouse to orbit, wheel or pinch to zoom.
The three-hit chain pays out a heavier finisher, and every swing costs wind
(stamina); a roll costs more, so a panicked roll at zero wind is refused.

## Stack

- [Babylon.js](https://www.babylonjs.com/) — WebGL2 rendering, procedural world
- [React 19](https://react.dev/) + [TypeScript](https://www.typescriptlang.org/) — shell, HUD, menus
- [Vite 7](https://vitejs.dev/) + [vite-plugin-pwa](https://vite-pwa-org.netlify.app/) — build and service worker
- IndexedDB (`idb`) — settings, records and the checkpoint save
- GitHub Actions + GitHub Pages — deploy on every push to `main`

No paid services, no CDN assets, no telemetry.

## Develop

```bash
npm ci
npm run dev          # http://localhost:5173/Pig-Legends/
npm run typecheck    # tsc, no emit
npm run build        # typecheck + production build into dist/
npm run preview      # serve dist/
python3 scripts/serve-dist.py 4174   # serve dist/ exactly like Pages does
```

`base` in `vite.config.ts` is `/Pig-Legends/` because the site lives under that
path on Pages. Any new asset must be referenced through the Vite base (an
`import`, or `%BASE_URL%`) or it will 404 in production while working locally.

### Repository layout

```
src/
  game/            engine, config, store, input, world, entities, systems
  react/           components, screens, hooks
  storage/         IndexedDB layer
  styles/          global CSS (the HUD is DOM over canvas, on purpose)
scripts/
  make-icons.py    regenerates the PWA icon set
  serve-dist.py    local Pages emulator: /Pig-Legends/ prefix + no-store
  shoot.py         headless screenshot + HUD readout
  probe.py         engine-state sampling with the ?debug=1 hook
  combat.py        closed-loop chase-and-swing test
public/
  icons/ favicon.svg robots.txt .nojekyll
```

### Test hooks

`?mode=hunt` skips the title card and starts a run — this is also what the
installed app's *New Hunt* shortcut does. `?debug=1` publishes the live engine
as `window.pigDebug`, which is how the harness scripts read player and wolf
state out of a hashed production bundle. Neither costs anything in normal play:
`pigDebug` is only assigned when the parameter is present.

## Deploy

`.github/workflows/deploy.yml` installs Node 22, runs `npm ci`, type-checks,
builds, and hands `dist/` to the official GitHub Pages actions. Pushing to
`main` publishes automatically; Pages must have **Source = GitHub Actions** in
*Settings → Pages*.

## Known limits of this prototype

This is the first playable cut, not a finished game. The models are procedural
placeholders built from primitives, one arena and one enemy type are all that
exist, and the wolf's steering is a distance-and-fan check rather than real
navigation. Everything is deliberately tuned so that adding meshes, biomes and
enemy kinds later means replacing a factory function, not rewriting the engine.
